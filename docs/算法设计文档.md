# 算法设计文档

> 本文说明项目正式五子棋算法的设计、参数边界、缓存语义和验证原则。正式运行路径是纯 Python、纯算法实现；我方神经网络能力已移除；外部教师程序和离线纯算法拟合仅属于显式实验能力，不自动进入正式决策。
>
> 代码事实以 `gomoku/` 当前源码为准，测试事实以当前测试文件和实际运行结果为准。有限搜索中的“必胜/必败”只对本次实际展开且未被剪掉的树成立，不表示全盘数学证明。

# 一、算法基础

## 1.1 范围、坐标与总流程

本项目实现 15×15、黑方先行的自由五子棋。核心坐标使用零基 `(r, c)`，其中 `r` 是行、`c` 是列；显示层使用 `A-O` 和 `1-15`。跨层转换必须明确，不能重复加一或交换行列。

正式决策链为：

```text
棋盘/真实着法
    -> PatternAnalyzer：方向记录与棋型子类
    -> Search：黑白状态表、战术候选、普通候选、攻防档位
    -> DeepSearch：温度递归、路径权重、剪枝、叶子评分、五态汇总
    -> Engine：开局接管、最终排序、可选决策网络回退
    -> GUI / CLI / protocol / Android 适配层
```

真实落子与搜索模拟落子是两条不同的状态路径。真实落子要推进棋局和搜索缓存；模拟落子只在当前分支内暂时改变棋盘和状态表，返回前必须完整恢复棋盘、状态表、历史、档位和分支上下文。

一次非开局决策的顺序是：

1. 读取当前行棋方的战术结果。
2. 命中直接战术时按战术候选取点。
3. 未命中时生成普通候选和候选权重。
4. 进入深推排序阶段，分别计算分数和五态。
5. 先按五态排序，再按候选分排序；若全是必败档，仍选择兜底着法。
6. 只有显式启用且真实推理成功的决策网络才可以覆盖纯算法第一名；失败时可观察地回退纯算法。

## 1.2 棋型分析

棋型分析对一个落点的四个方向分别扫描。单方向设计流程是：

```text
_scan_two -> _overall_judge -> _normalize -> _classify -> 子类编码
```

扫描从落点向两侧进行，保护第一条缝，第二条缝或连续四子时截断不相关的远端棋子。双缝三子 `x_x_x` 优先判作整体眠三；连续四、连续五优先保留落点所在连续段，避免把活四误判成带缝眠四。边界、对手子和越界都作为封端处理。

四方向最高档组合编码为 18 个子类：

| 编号 | 名称 | 父类 | 含义 |
|---:|---|---|---|
| 0 | `five` | KILL | 成五 |
| 1 | `live4` | KILL | 活四 |
| 2 | `d44` | KILL | 双眠四 |
| 3 | `d34` | KILL | 眠四加活三 |
| 4 | `d33` | KILL | 双活三 |
| 5-8 | `a1_bbb` 至 `a1_ccc` | THREAT | 眠四/冲四系 |
| 9-12 | `a2_bbb` 至 `a2_ccc` | THREAT | 活三系 |
| 13-16 | `b_bbb` 至 `b_ccc` | POTEN | 眠三/活二潜力系 |
| 17 | `none` | USELESS | 无用 |

方向档位是 0 至 5：五连、活四、眠四、活三、眠三/活二、眠二/无。父类和子类是状态表的基础数据；父类优先级服务于候选分流，子类编号服务于候选评分、攻防档位和叶子评估。

棋型版本开关为 `USE_SUBCLASS=True`，正式路径使用 18 子类。去掉 4 个低配维度的版本只是预留，不是当前正式能力；因此 `USE_SUBCLASS` 属于结构版本参数，修改后必须重新建立状态表并使搜索缓存失效。

## 1.3 状态表、增量更新与回滚

搜索层持有黑白两张 15×15 状态表。每个空点保存对应行棋方若在该点落子会形成的 18 子类编号；已占点不进入候选。

落子后，`SearchScope` 提取落子所在棋段：以对手子、边界或连续三空为界，取段内缝隙和两端全部尾部空位。该区域刷新后，与全盘逐格重算一致，不再使用旧的固定邻域或“状态区”兜底。

模拟落子必须具有事务式回滚边界：

```text
写入棋盘
  -> 暂时更新棋盘和状态表
  -> 读取候选/战术/棋型
  -> 恢复所有被修改的状态
  -> 清除分支和上下文
```

验证重点是：模拟状态能看到本分支新形成的威胁，且分支结束后状态完全回到进入前。黑白两方必须使用同一条更新路径；黑先只属于规则和开局入口，不构成状态表更新差异。

## 1.4 固定算法契约

以下内容属于固定规则，不作为普通连续参数拟合：

| 契约 | 当前规则 |
|---|---|
| 棋盘 | 15×15，自由五子棋，黑方先行 |
| 状态表 | 黑白分离，18 子类，0-4 为必杀档，17 为无用 |
| 候选上限 | 根层与内部普通候选固定 4 点（2 攻 2 防）；战术候选沿原规则 |
| 视角 | 每个实际落子节点描述该节点落子方；直接子节点是对方应手 |
| 终局 | 实际成五优先，评分为 `+1000/-1000` |
| 五态 | `+1` 必胜、`+2` 存在必胜、`0` 未确定、`-2` 存在必败、`-1` 必败 |
| 对称 | 黑白逻辑、根层和递归层、状态更新和回滚对称 |
| 回滚 | 所有模拟状态必须恢复到调用前 |
| 正式依赖 | 不依赖 Torch、NumPy、模型或教师进程 |

# 二、候选生成与局面判断

## 2.1 战术候选和防守候选

战术候选层返回 `(reason, points)`。`reason` 是候选生成的战术优先级标签，`points` 是带权坐标字典；二者同时供顶层取点和深推零耗温判断使用。

检测顺序固定为：

```text
my-five -> opp-five -> my-vcf -> opp-vcf -> my-d33 -> opp-d33
```

其中：

- `my-five`：本方存在直接成五点，权重 100；
- `opp-five`：对方存在直接成五点，必须直接堵，权重由防守候选产生；
- `my-vcf`：本方活四、双眠四、四三等强制链，权重 100；
- `opp-vcf`：对方强制链的反推堵点，中心点通常 100，端点或缝点 80；
- `my-d33` / `opp-d33`：本方或对方双三及其防守点。

本方四三会经过“反四”检查：如果对手唯一堵点同时形成可用四型，三步杀降级，不再作为本方必杀候选。状态表本身不因该次先手判断改写，只改变本次候选身份。

防守候选通过临时模拟威胁方落子，再读取活四、眠四、活三的端点和缝点。距离为 1 的近端是合法防守点，不能一律排除；临时模拟期间棋子必须留在棋盘上，结束后恢复。

当前防守权重是：杀型中心点 100、杀型端点和缝点 80；非杀型活三防守路径保留 60 的旧接口。它们是候选权重，不是叶子分，也不能转成统一的等权列表。

深推的“必杀判定”只指这里的候选生成分支：命中 `reason` 后直接取点；未命中才进入普通候选评分。它不等于五态必胜/必败，也不等于全盘扫描 0-4 档，更不等于刚落点的棋型类别。


两个防守档 `opp-vcf`、`opp-d33` 使用同一合并规则。只处理当前优先级命中的来源，不跨档改写战术优先级：

```text
E = 该档每个威胁来源的原防点并集
D = 这些原防点的交集
C = 本方可形成四的点（沿现有FOUR_GRADES）
候选 = E∩C（若非空），否则 D
```

先筛并集中的冲四兼防点，不先用D筛C，也不把E外纯冲四补入。高优先级的本方直接成五、对方堵五、本方VCF及原反四降级规则保持。实现只需检查E各点的本方状态表，等价于E交全盘C，不必额外扫描空盘面。结果保留E首次出现的顺序；同点多来源的权重仍取原最大值（中心100、端点/缝80），不重新排序或等权化。单来源没有冲四兼防点时，D就是其原防点集。

若最后候选为空，返回 `(原防守reason, {})`，与 `(None,{})` 的普通空候选区分。根、递归本方待走入口、对方无应手及缓存叶子续推都识别为 `no_common_defense` 结构终止，不再退回普通候选或遮成普通温度耗尽。防守选择层硬败，上一实际进攻落子节点硬胜，沿原硬态规则回传；不会将败势越两级直接翻转。调试录像增加“复合防守无解”事件，并保留结束原因。

这个硬结论只针对新候选政策的搜索范围：E外冲四有意不纳入，单来源提取也仍是现有启发式，不能宣称全盘合法着法穷举证明。评分暂沿原静态叶子公式，不新增状态分或固定±1000替代；这是新终止位置的叶子估值，不宣称保持旧并集树的加权分。真正成五的原终局分保持。真实根仍给出合法的必败兜底着法，但不把兜底重新当成可行防守子树展开。

候选政策标识纳入既有缓存身份；不混用旧并集树。已完成无解硬态可直接复用，既不再次拨温，也不重新生成中间候选。

## 2.2 普通候选评分参数

未命中战术时，普通候选层使用棋型基础分、邻近度和攻防一体分生成候选；根层与内部深推统一固定 2 攻 2 防、最多 4 点。候选权重必须保留，不能静默转换成等权列表。

| 参数 | 当前值 | 作用 | 当前性质 |
|---|---:|---|---|
| `TYPE_SCORE` | 18 子类字典 | a1/a2/b 系基础分 | 可调 |
| `PROX_DIST_W` | `{1:1.0, 2:0.5}` | 切比雪夫距离衰减 | 可调 |
| `PROX_DIR_W` | `line=2.0, other=0.5` | 同线/异线价值 | 可调 |
| `NEIGHBOR_W` | attack `(110,-10)`；defend `(30,70)`；dual `(60,40)` | 自家与对家邻近组合 | 可调 |
| `W_NEIGHBOR` | `30.0` | 邻近度对综合分的总影响 | 可调 |
| `NEIGHBOR_NORM` | `600.0` | 邻近分归一化分母 | 可调 |
| `DUAL_BONUS` | `30.0` | 同时具备攻防价值的加分 | 可调 |
| `SCORE_MAX` | `260.0` | 综合分标准化满分 | 与上项联动 |

普通候选权重最后 clamp 到 `[1, 100]`。这不是显示分数，而是同时影响候选排序和温度耗费；权重越高，单步耗温越低。

## 2.3 攻防档位参数

档位根据当前压力差和历史 0 级杀势动量选择攻防配比。压力统计只读取威胁和潜力父类，0 级即时必杀由战术候选优先级单独处理。

| 参数 | 当前值 | 作用 | 当前性质 |
|---|---|---|---|
| `GEAR_ENABLED` | `True` | 是否启用动态档位 | 运行开关 |
| `GEAR_PROFILE` | 1档 `(1,4)`；2档 `(2,3)`；3档 `(3,2)`；4档 `(4,1)` | 攻防候选数量 | 规则配置 |
| `DEFAULT_GEAR` | `3` | 无法确定压力时的档位 | 可调 |
| `GEAR_W_A1` | `4.0` | 眠四/冲四压力权重 | 可调 |
| `GEAR_W_A2` | `2.0` | 活三压力权重 | 可调 |
| `GEAR_W_B` | `0.5` | 潜力压力权重 | 可调 |
| `GEAR_W_ZERO` | `5.0` | 历史 0 级动量权重 | 可调 |
| `GEAR_ZERO_WINDOW` | `10` 手 | 历史杀势窗口 | 可调 |
| `GEAR_THRESHOLDS` | `(2.0,-1.0,-3.0)` | 压力差到 1-4 档的分界 | 可调，但需保持顺序 |

档位改变会改变根候选覆盖和树结构，因此会使跨回合搜索树身份失效；不能只复用旧叶子分数。

## 2.4 候选覆盖边界

候选生成是深推的输入上限。叶子评分更精确，不能找回未进入根候选的强着。当前正式边界是：

- 战术候选命中即进入战术分支；
- 根层普通候选最多 5 点，按动态攻防档位补入；
- 根层与内部普通候选固定 2 攻 2 防、最多 4 点；
- 候选权重和防守权重必须原样进入温度、路径质量和剪枝；
- 空候选、唯一候选、已占点和全部败势均保留合法兜底行为。

# 三、深推、五态与缓存

## 3.1 温度、路径权重与剪枝参数

普通落子的耗温为：

```text
dt(w) = DT_M * ((100 - w) / 100) ^ DT_POW + DT_N
```

战术候选按当前落子前的 `tactical_candidates` 身份免耗温；普通候选即使权重为 100，仍消耗 `DT_N`。正温度可以扣到负数，但不改变本步原有耗温。

| 参数 | 当前值 | 作用 | 当前性质 |
|---|---:|---|---|
| `T0` | `160.0` | 每条根候选路径的初始温度；GUI 可切 80/160/240 | 运行时可调 |
| `OPENING_COLD_T0` | `160.0` | 开局冷启动温度 | 当前发布值 |
| `MIDDLE_COLD_T0` | `120.0` | 中局冷启动温度 | 当前发布值 |
| `DT_M` | `400.0` | 权重曲线的主耗温系数 | 可调 |
| `DT_POW` | `2.0` | 权重曲线幂次 | 可调 |
| `DT_N` | `3.0` | 每步最低耗温 | 可调 |
| `CAND_N_FULL` | `5` | 兼容普通候选请求上界；战术候选不按此值截断 | 当前固定 |
| `CAND_N_ORDINARY` | `4` | 根层与内部普通候选上限（2攻2防） | 当前固定 |
| `PRUNE_W` | `0.02` | 绝对路径权重低于该值时剪枝 | 可调，但需保留最强分支 |

候选质量在本层候选集合内归一化：

```text
q  = 本方候选权重 / 本层本方最高权重
oq = 对方应手权重 / 本层对方最高权重
```

根层路径权重只使用对方应手质量；根层以下使用 `path_w × q × oq`。分数回传是本层保留分支的加权平均，绝对路径权重只用于剪枝，不直接放大分数。

## 3.2 根层与递归层流程

根层对每个外部候选执行：

1. 读取入口温度和当前方的战术身份。
2. 模拟本方落子并更新状态表。
3. 实际成五时立即返回 `+1000` 和硬胜种子。
4. 温度耗尽时检查下一方的战术候选；若未命中战术直接取点分支，在当前盘面形成 `stale` 叶子。
5. 否则展开对方应手；对方实际成五立即形成 `lose` 叶子。
6. 非终局应手回到本方待走入口，递归层再次检查温度和战术身份。
7. 汇总对方应手分数、五态和兼容统计，恢复所有模拟状态。

递归层流程相同，但根层与内部候选统一固定 2 攻 2 防、最多 4 点，并额外携带路径权重和直接候选状态。对方普通应手结束后，本方不能因为温度为负而无条件补走普通步；只有候选生成命中战术直接取点分支才能继续。

## 3.3 五态判定与向上汇总

五态使用带符号整数：

| 状态 | 含义 | 是否硬结论 |
|---:|---|---|
| `+1` | 必胜 | 是 |
| `+2` | 存在必胜，表示对手有失误机会 | 否 |
| `0` | 本次搜索未确定 | 否 |
| `-2` | 存在必败，表示本方有失误风险 | 否 |
| `-1` | 必败 | 是 |

硬结论按双方最优选择回传：任一有效子节点对其落子方硬必胜，则当前节点硬必败；所有有效子节点对其落子方硬必败，则当前节点硬必胜。实际成五直接提供硬胜种子，不要求此前每步都是强制威胁。

当前节点未确定时，只读取直接局部证据：本方直接孙节点有硬必败，产生 `-2`；否则对方直接子节点有硬必败，产生 `+2`；其余为 `0`。软状态不翻转、不当作硬证据向父层传播，也不扫描任意深层败点。

最终排序固定为：

```text
必胜 > 存在必胜 > 无 > 存在必败 > 必败
```

有非必败候选时不得选择必败候选；若所有合法候选都是败势档，按状态和分数选择兜底着法。`score` 与 `state` 分离，分数不能冒充胜败。

## 3.4 跨回合缓存与叶子续推参数

真实落子后，搜索树沿对应子节点换根；未命中则重建。缓存按完整棋盘键和真实落子路径组织。纯局面派生结果可以共享，欠温、展开进度和聚合分只属于当前路径。

温度耗尽的旧末端 `frontier` 记录：行棋方、旧温度、累计路径权重、停止时评分、深度、五态、搜索 epoch 和相位。实际成五及已有硬胜负直接使用缓存，不续推；`state=0、+2、-2` 采用同一续推公式。

恢复基线为：

```text
base = max(0, T0 + min(0, old_temperature))
```

低权重或过深叶子直接停止：

```text
path_weight < CONTINUE_W_MIN  -> 停止
depth >= CONTINUE_DEPTH_STOP   -> 停止
```

其余旧叶子的续推温度为：

```text
w = clamp(path_weight, 0, 1)
s = min(abs(score) / WIN_SCORE, 1)
d = depth / CONTINUE_DEPTH_STOP

T_continue = clamp(
    base
    + CONTINUE_WEIGHT_GAIN * f_w(w)
    + CONTINUE_SCORE_GAIN  * f_s(s)
    - CONTINUE_DEPTH_PENALTY * f_d(d),
    0,
    CONTINUE_T_MAX
)
```

当前独立参数为：

| 参数 | 当前值 | 作用 |
|---|---:|---|
| `CONTINUE_W_MIN` | `0.10` | 低权重叶子硬门槛 |
| `CONTINUE_DEPTH_STOP` | `8` | 深度硬门槛 |
| `CONTINUE_WEIGHT_GAIN` | `8` | 权重增益 |
| `CONTINUE_WEIGHT_POW` | `1.5` | 权重曲线 |
| `CONTINUE_SCORE_GAIN` | `16` | 评分绝对值增益 |
| `CONTINUE_SCORE_POW` | `1.5` | 评分曲线 |
| `CONTINUE_DEPTH_PENALTY` | `24` | 深度惩罚 |
| `CONTINUE_DEPTH_POW` | `2` | 深度惩罚曲线 |
| `CONTINUE_T_MAX` | `40` | 续推温度上限 |

同一真实换根 epoch、同一行棋方和同一相位只恢复一次。命中门槛后，即使当前盘面有战术点，也不能绕过旧叶子续推门槛。当前步原有耗温规则不改变，不补温、不清欠温；黑白对称。

## 3.4.1 单次冷搜索的完整结果复用

纯算法新树冷搜索可建立本次分析专用的完整结果表。它只在无trace、无实例叶子评分器替换且根节点尚无旧树结果时启用；旧树换根、叶子续温不使用此表。分析正常返回或异常退出时释放，不跨回合保存。

结果键精确包含完整棋盘、行棋双方、主评分方、入口温度、绝对路径权重、分支深度、完整历史键和本次入口温度。只有全分阶段已经完整返回、路径节点仍保有本epoch完整结果及完整落子结果的子树才能命中；判态阶段和部分累计分不得写入或使用该表。

命中后七项递归结果原样返回，同时复制已有子树的节点与路径状态。每个父节点仍按原分支权重分别计入同一分数，逐层归一加权、五态、直接子孙证据和排序定义均不改变；不把硬状态替换成固定评分，不合并两个父节点的贡献。

复制后的children、递归结果字典、frontier、resume信息与move_result各自独立，防止真实换根后的欠温和续推串到另一条路径。战术、候选、叶子值及特征等纯局面缓存继续沿用既有共享策略。复制整棵已完成子树有时间成本，且保留各路径树节点；该机制不保证长战术树在固定时限内结束，性能收益需另行测量。

## 3.4.2 梯度耗温、3点分批与战术截断评分

当前发布候选 `TACTICAL_FREE_PLIES=8`：路径上只有落子前属于当前战术候选的实际走法才累计一次；双方都计，普通步不递增也不重置，兄弟分支各继承父层计数。前8步免费，此后8步每手耗温2、再8步4、随后每手8；`TACTICAL_EXTENSION_PLIES=None`，没有额外的温尽后8手赠送。仍有正温度时允许按原扣温方式产生欠温；温度不大于0后只允许尚未用完的免费战术额度，下一战术步需要正温费用时按既有预算截断，直接成五优先实际终局。

节点、frontier和诊断上下文保存`tactical_count`，完整递归结果键、冷算共享键及叶子值键区分此计数，策略参数由原树身份机制核验。真实换根保留已累计次数，不重新领取免费额度；旧边不重扣温，叶子恢复沿原续温门槛，新增边从已用次数继续。新树才从0开始。

当前发布候选 `TACTICAL_BATCH_SIZE=3`：每个节点本回合先展开原顺序前3个战术候选，其余候选、权重及温度上下文保留在`pending_edges`；后续真实换根时由既有机制补推。未完成分支保留`score_complete=false`，不得把部分搜索返回当作完整搜索结果；已完成的硬胜败仍按原规则定分，pending不是永久丢弃，换根正常裁掉的旁支也不等同于pending丢失。

实验策略下，仍有战术而预算截断的叶子标记`leaf_end_reason='tactical_budget'`及`to_move`，普通结束仍为`temperature`。前者不直接把`opp-*`原因映射成负分，也不另加反四奖励：对当前行棋方s的当前档位全部合法候选做一层journal模拟（至多棋盘空点数，无隐式8点截断）。实际成五使用原终局分；否则按下一行棋方t=3-s调用原静态评分，再转回主评分方m，即`t==m`取原值、否则取负。所有候选依原权重归一汇总，不取最优分替代加权。

该评分探针不再递归延伸战术，不增加保存搜索树的路径计数。`tactical_probe_moves`单独记录模拟数量，`tactical_cutoffs`记录实际计算的战术截断叶子数；命中叶子值缓存不重复计数。静态函数及数值尺度沿原实现，没有新增奖励分或±1000裁剪。普通叶子仍走原静态分。

战术未决与分数未计算完整是两件事：本预算规则下完成的叶子估值可正常回传，`score_complete=True`；截断本身不产生硬胜败。原判态早停造成的部分累计分仍使用`score_complete=False`。逐层加权回溯、五态传播及排序不改，但开启实验会改变搜索末端和评分，不能要求与关闭实验相同；同一策略下缓存开关仍须保持结果一致。

这是一种待性能与选点实验检验的截断估值，不宣称已经解决长强制链或提升棋力。一层应手也有实际开销，须与主树展开量分开计入；完整对照由实验任务执行。

## 3.5 模拟状态恢复和缓存失效

缓存身份包括 `DeepSearch` 大写常量、`search` 模块权重和关键方法对象。修改正式参数、候选评分、叶子评分、温度、剪枝或续推参数后，旧树不能继续作为同身份结果使用。

一次根节点判态与补分只在本次决策内有效，不跨回合。早停产生的部分累计分不能写成完整结果；只有完整递归结果和纯局面叶子结果进入跨回合树缓存。

缓存统计包括战术、候选、叶子、特征、子树、冷算完整结果 `cold_result_hits` 和 `frontier_resumes` 命中数。缓存命中不计为新叶子，不把缓存省下的计算称为算法本身提速。

# 四、叶子评分与最终决策

## 4.1 叶子评分参数

叶子评估区分实际终局和温度耗尽的僵持叶子：

- `win`：当前决策视角实际成五，返回 `+WIN_SCORE`；
- `lose`：对手实际成五，返回 `-WIN_SCORE`；
- `stale`：读取停止时当前棋盘的黑白状态表，不读取旧上下文快照。

`stale` 评分优先级为：当前决策方成五点、对方成五点、当前决策方强必杀、对方强必杀、当前决策方弱必杀、对方弱必杀；双方都没有 0-4 必杀档时，才计算 5-16 子类的全盘基础分差。

| 参数 | 当前值 | 作用 | 当前性质 |
|---|---:|---|---|
| `WIN_SCORE` | `1000` | 实际成五终局分 | 固定量级 |
| `KILL_VALUE_WIN` | `920` | 当前方成五点档 | 可调但需保持档位顺序 |
| `KILL_VALUE_WIN_OPP` | `-920` | 对手成五点档 | 与上项对称 |
| `KILL_VALUE_STRONG` | `850` | 当前方强必杀档 | 可调 |
| `KILL_VALUE_STRONG_OPP` | `-700` | 对手强必杀档 | 可调 |
| `KILL_VALUE_WEAK` | `650` | 当前方弱必杀档 | 可调 |
| `KILL_VALUE_WEAK_OPP` | `-500` | 对手弱必杀档 | 可调 |
| `MY_SUB_VALUE` | 5-16 子类字典 | 当前决策方全盘基础分 | 可调 |
| `OPP_SUB_VALUE` | 5-16 子类字典 | 对手全盘基础分 | 可调 |
| `GEAR_OPP_COEF` | `{1:1.2,2:1.1,3:1.0,4:0.9}` | 对手总和的档位倍率 | 可调 |
| `LEAF_TAX_R` | `0.05` | 大分差的长期边际比例 | 可调 |
| `LEAF_TAX_S` | `500` | 平滑压缩过渡尺度 | 可调 |
| `THREAT_BONUS_WHITE` | `100` | 历史威胁奖励遗留值 | 不参与当前叶子分 |
| `THREAT_BONUS_BLACK` | `50` | 历史威胁奖励遗留值 | 不参与当前叶子分 |

无必杀时：

```text
D = my_total - gear_coef * opp_total
x = abs(D)
leaf = sign(D) * (LEAF_TAX_R*x
       + (1-LEAF_TAX_R)*LEAF_TAX_S*(1-exp(-x/LEAF_TAX_S)))
```

叶子分是局面评价，不是胜率；静态高分也不能直接推出五态必胜。

## 4.2 叶子分到根候选分

每个对方应手产生一个子树分。根候选分是保留应手的相对权重加权平均：

```text
root_score = Σ(opp_quality * child_score) / Σ(opp_quality)
```

递归内部本方候选和对方应手也采用本层保留分支的加权平均。路径权重用于剪枝；公共路径因子在同一层平均中抵消，不直接放大分数绝对值。

`state` 的合并独立于 `score`：硬状态按最优选择传播，软状态只读取直接子/孙节点；不能用高分覆盖状态，也不能用深层状态直接覆盖候选根节点。

贡献汇总只是独立诊断报告，不参与或替换正式选棋评分。

## 4.3 状态优先与候选排序

候选结果中的 `state`、`state_name`、`child_state`、`forced` 必须来自同一套五态判定。排序键为状态档位优先、同档分数降序：

```text
STATE_WIN          -> 4
STATE_EXISTS_WIN   -> 3
STATE_NONE         -> 2
STATE_EXISTS_LOSE  -> 1
STATE_LOSE         -> 0
```

在判态模式中，找到非必败候选后，后续硬败候选允许早停；已被证明为硬败且有非硬败替代的候选可以返回 `score=null, score_complete=false`。所有参与比较的非硬败候选和全硬败局面必须补齐完整分数。

## 4.4 最终选点流程

最终选点共享同一条决策链：

- 本方前三手命中可靠完整棋谱时，可由开局模块接管；成五和必须堵五优先交回正式战术逻辑；
- `my-five` / `opp-five` 属于直接战术取点；
- 普通候选不因唯一性自动获得五态结论；唯一候选只表示候选覆盖后的唯一输入；
- 其余候选进入深推，输出完整 `ranked`、状态、分数和叶子评估状态；
- 决策网络默认关闭，只有真实推理完成才允许覆盖纯算法第一名；加载失败、未启用或异常时回退并保留可观察原因。

# 五、算法边界与验证

## 5.1 正式算法边界

适配层只负责输入输出、会话和坐标转换，不复制候选、评分、深推或成五规则；所有选点都回到同一条核心决策链。Android 与其他宿主使用同一套纯算法设计，宿主差异不改变状态、候选和五态语义。

正式运行路径不依赖 Torch、NumPy、模型权重、教师 EXE 或实验目录。叶子网络、决策网络、模型加载与NN采样训练入口已移除，叶子始终由纯算法计算。服务层旧三元组及JSON中的 `net_used` 仅为协议兼容保留，固定为 `False`；不能启用网络。

引擎运行开关和上下文参数如下：

| 参数 | 当前默认 | 作用 | 性质 |
|---|---|---|---|
| `rank_candidates(..., complete_scores=...)` | `False` | 是否跳过判态早停并补齐全部分数 | 调用上下文 |
| `DeepSearch.T0` 预设 | `80/160/240` | GUI 的低/标准/高温度档 | 运行时配置 |
| 协议 `--t0` | 不传保留开局160/中途120/续温160 | 显式传入时同时覆盖三种温度 | 入口配置 |

`Engine._rank_search` 根据是否已搜索/导入判断冷启动类别；单独赋值 `T0` 不改变另外两个冷启动常量。协议显式 `--t0` 和离线 `parameter_scope(params, t0)` 因而必须同时设置三者；离线作用域包括异常退出均恢复原值。自对弈CLI未指定参数文件和 `--t0` 时沿用正式默认，指定参数文件时使用该方的 `deep_t0`，显式 `--t0` 优先；这不修改普通/战术候选与耗温规则。

历史经验修正来自 `memory.py`，不属于五组核心搜索参数。当前参数为 `MEM_W_WIN=2.0`、`MEM_W_LOSE=-3.0`、`MEM_ADJ_MAX=15.0`；它们会改变根候选权重，因而可能改变搜索树。需要做算法比较、离线拟合或复现实验时，必须显式关闭或把记忆作用域写入实验身份。

## 5.2 参数变更和缓存影响

参数的影响范围必须在文档参数表中明确：

| 参数类型 | 是否进入搜索身份 | 旧树是否可复用 |
|---|---|---|
| 棋型编码、状态五态规则 | 是 | 否 |
| 候选评分、攻防档位 | 是 | 否 |
| 温度、剪枝、候选数量 | 是 | 否 |
| 叶子分和倍率 | 是 | 纯局面值需重新核验 |
| 跨回合续推参数 | 是 | 否 |
| 显示格式、日志文本 | 否 | 可以，但不得改变决策字段 |

改变候选、档位、历史窗口、温度、剪枝或续推策略，会改变搜索树结构；不能只复用旧叶子表达式或旧统计结果。实验输入、源码指纹、解释器版本和搜索设置必须绑定到实验目录。

## 5.3 验证与证据范围

验证按算法不变量组织，而不是按单局结果组织。深推和缓存相关验证至少覆盖：

- 战术零耗温分支可以越过耗尽温度，普通评分分支必须停止；
- 普通候选不会因为权重 100 冒充零耗温；
- 真实成五优先于下一行棋方和负温度；
- 黑白对称，根层和递归层一致；
- `reason` 来自候选生成，不使用 `_has_kill_points`、全盘原始 0-4 扫描或刚落点棋型类别替代；
- `state=0、+2、-2` 的叶子续推参数单调性成立，低权重和深度上限正确停止；
- `+1/-1` 和实际终局直接使用缓存，不继续展开；
- 同一 epoch 不重复恢复温度；
- 模拟结束后棋盘、状态表、历史、档位、分支和上下文完全恢复；
- 冷算和真实落子换根后的热算在同一搜索身份下结果一致；
- 缓存命中不冒充新增叶子或完整新搜索。

有限回归通过只说明对应路径满足当前测试，不说明所有棋局、所有候选和所有深度都已穷举。任何中止、资源保护、缓存缺项或超预算都必须按部分结果报告，不能称为完成。

## 5.4 离线调参与证据边界

离线工具与正式引擎分离。可以拟合的正式参数主要来自五个参数模块：

1. 候选评分参数；
2. 攻防档位参数；
3. 深推资源与剪枝参数；
4. 叶子评分参数；
5. 跨回合叶子续推参数。

棋盘尺寸、18 子类编码、五态合并、战术优先级、黑白对称和回滚契约不是普通连续拟合项。候选、温度、剪枝和续推参数会改变树结构，必须重新搜索；只改叶子数值且结构证明未变时，才可以在绑定身份的离线记录上复算。

离线 `RecordingSearch` 在实际静态评分入口 `_stale_result_score` 附加叶子表达式，覆盖普通温尽叶子及战术预算截断内的一层静态应手探针。探针先按下一行棋方评分，取负转换视角时表达式也必须取负；不能将依赖叶子参数的探针评分存成常量。硬胜败和命中固定战术档位的评分仍记为常量，记录开关不改变原生数值。

教师输出只作已授权的离线比较，不是本方引擎真值，不把有限主变化称为全盘证明。正式调参需要记录输入棋局家族、黑白交换、解释器、预算、源码指纹、参数范围、接受门槛、停止原因和实际资源消耗。

离线实验默认关闭 NN 和经验修正，不把一次局面、单条主变化、缓存命中或有限叶子统计推广为全局棋力结论。正式引擎默认参数只能在明确验收后修改，实验参数不得隐式写入正式运行路径。

## 5.5 桌面搜索树录像与缓存续温观察

`DeepSearch._debug_observer` 默认是None；不开调试窗口时不创建录像、进程或调试文件。观察钩子放在实际搜索节点登记、候选查询、保留边、实际落子扣温、叶子评分、结果回传、硬态早停、换根、完整缓存命中及旧叶子恢复温度的位置。观察数据不参与候选/权重/温度/剪枝/五态/排序的计算，也不进入缓存身份。该功能不会把战术精筛研究原型接入正式决策。

`gomoku/tools/search_trace.py` 以节点对象分配持久ID，并记录父节点、实际着法和严格递增事件序号。同盘面不同路径仍是不同节点；冷算完整子树复制以缓存导入标记，不把导入节点伪称逐个展开。每轮记录起点和T0；真实落子换根与其后叶子续推沿原核心执行。续温记录旧欠温、恢复后有效温度、权重/深度/旧评分及是否被门槛拦截；同epoch重复读取不假报再次拨温。状态描述节点落子方，score另标主评分方。

时间轴模型按每个节点截至当前事件的记录重放，不读取未来分数或未来新增节点。静态叶子评分的一层应手模拟不经过“实际搜索落子”观察点，所以不混入递归树。硬态早停事件单独记录根候选和待回传层数，不把它误说成当前所有分数已经完整。

`gomoku/tools/search_tree_gui.py` 以Frame面板嵌入复盘窗口的“搜索树”页签，只在Tk主线程绘制；独立单进程持有引擎与缓存，通过批量队列发送事件。GUI的录像暂停只影响播放；“暂停搜索”通过进程事件协作暂停计算，资源墙钟继续计时。停止或资源边界可打断模拟，因此整个调试引擎进程必须丢弃，不能将打断时的棋盘/树用于下一次续算。主对局和原始棋谱不受影响。

调试进程使用独立临时记忆目录，开局谱和算法参数沿实际入口运行。搜索树页默认T0=160，可在面板内调整。T0改变仍按原缓存身份规则失效，不复用旧身份。源局面来自已导入棋谱的当前手/试走分支。同一源局面再次载入只切换页签，不清掉原面板缓存；不同手数会替换已停止或空闲的面板。切换页签不停止当前搜索，也不改变原谱手数。开始时不复制主窗口大树；要测缓存阶段，应在同一调试会话中先搜索、真实走双方两手，再搜索同一主评分方。

绘制有深度/节点数限制，录像有明确事件上限；它们不能被表述为算法剪枝。记录与进程通信会带来额外开销。本功能属于源码调试入口，不代表已打包资产具备能力，也不提供棋力或性能收益证明。
