# 实验命名规范

本规范适用于新建的本地实验目录。实验默认位于仓库的 `storages/experiments/`，继续受现有 Git 忽略规则保护。命名规范不产生运行、改参数、追加预算或发布授权。

## 目录命名

统一格式：

```text
YYYYMMDD-主题-具体目的-NN
```

| 字段 | 规则 |
| --- | --- |
| 日期 | 首次创建日，北京时间，八位年月日；跨天续跑不改名 |
| 主题 | 使用下表中的固定词，便于检索和分类 |
| 具体目的 | 写清本次要回答的问题或比较对象，使用简短中文；引擎名、版本号等保留原名 |
| 序号 | 从 `01` 开始；同日、同主题、同目的的新独立实验依次递增；不覆盖已有目录 |

固定主题：

```text
搜索缓存、搜索性能、候选宽度、战术判定、叶子评分、棋力对战、
参数拟合、开局库、败局复盘、发布验证
```

示例：

```text
20261102-搜索缓存-跨回合耗时-01
20261102-候选宽度-三四五候选对比-01
20261102-战术判定-无效防点排查-01
20261102-棋力对战-TPTC黑白交换-01
20261102-参数拟合-叶子评分校准-01
20261102-发布验证-v1.12.1-01
```

不要单用 `test`、`vnext`、`final`、`new2`、`smoke` 等表达目的。冒烟也要写明对象，例如 `20261102-搜索缓存-换根冒烟-01`。目录名不用空格或 Windows 路径非法字符 `<>:"/\|?*`。

温度、候选数、并发、随机种子、预算和源码指纹等完整配置写入实验说明及身份文件，不全部堆进目录名；当某项就是比较对象时，可在目的中出现。

## 一个实验与多次运行

同一实验的不同配置或运行放在子目录中，使用能看懂的中文名称，例如：

```text
20261102-搜索缓存-跨回合耗时-01/
  实验说明.md
  结果摘要.md
  runs/
    冷算-01/
    同盘面命中-01/
    跨回合命中-01/
```

- 同身份断点恢复沿用原目录，保留原预算和日志。
- 修复实验脚本后创建新的运行子目录，保留失败尝试；源码或评价口径改变时绑定新身份，不覆盖旧结果，不冒充同身份续跑。
- 研究问题或方案变成新的独立实验时，新建根目录并记录与前一实验的关系。
- 完成、失败、超时、预算耗尽等状态写进结果摘要和状态文件，不通过改目录名表达。

## 最少提供的中文入口

| 文件或目录 | 必须说明的内容 |
| --- | --- |
| `实验说明.md` | 研究问题、输入与基线、配置与身份文件位置、预算、判定标准 |
| `结果摘要.md` | 当前状态、已完成与未完成项、主要结果与限制、原始证据链接；无结果时明确写尚未运行或未完成 |
| `runs/` | 各次运行的原始记录；由现有工具产生在其他位置时，保留原路径并在中文入口说明 |

已有工具要求的 `plan.md`、`summary.json`、`state.json`、日志和断点继续使用，不为中文命名重写协议或重复维护机器状态。中文入口负责说明和导航，不能把命令启动成功写成结果已验证。

## 历史目录与索引

旧实验目录暂不改名、不搬动，不修改原始报告、日志、身份和缓存路径。通过本地实验索引补充中文名称或说明；新增实验按本规范命名，并补入索引。

历史名称不能作为完成或推荐依据。引用某次结果时，仍须核对它的源码、输入、配置和停止原因。
