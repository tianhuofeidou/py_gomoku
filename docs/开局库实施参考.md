# 开局库实施参考

本文件整理 DS 的研究与本轮核读的人类棋谱资料。当前源码的正式接管来源是整盘前5手稀疏库（黑一 H8、白二两类相邻、黑三27条、白四74条、黑五429条）；人类经典推荐与后续研究线只在本方第四次落子起补一个根候选，不再接管落点。棋力提升仍须另行对战验证。

## 先做什么

先补覆盖，再增加深度：以标准 26 种三手棋形作目录，逐一整理白四应手，再延伸黑五、白六。26 种只是常见棋形目录，不能覆盖所有合法开局，也不能据此声称查谱命中率达到 100%。

每个局面先收录人类资料明确讨论的主要应手、备选应手和常见弱防。弱防用于检验引擎能否惩罚失误，不作为随机开局的可选着法。坐标未辨认清楚的图中 a/b/c 点保留来源，暂不生成正式记录。

优先处理白二贴身的正邻、斜邻两类，解决目前白二选择过于单一的问题。隔一路在自由规则下合法，可以保留为研究分支；不能凭少量样本直接认定其强弱。

| 来源 | 用途 | 使用边界 |

| [RIF 开局资料](https://gomoku.renju.net/openings/)及本地 RenjuNet 数据 | 棋形命名、安排覆盖优先级 | 不将混合规则的频率或胜率直接当成自由五子棋最优策略；原始棋谱不入库 |

人类定式说明决定哪些着法可以作为推荐；统计只安排覆盖优先级；现有自由规则算法评估未评级的后续研究线。不会让求解器重新选择全部主着后仍称作人类定式。

## 与当前引擎怎样衔接

保留“固定根落点、继续建树”的接管边界，接管范围改为整盘第1-5手（双方合计，着手前盘面最多4子）：直接成五、堵五优先；第6手起不再接管，也不会回落到旧库接管。提前出谱立即交回现有候选与深推；原候选池为空时才补合法点。

继续用完整棋盘、黑白颜色和当前行棋方查谱，珠型只作标签。多种落子顺序到达相同盘面时应合并记录。研究统计可以将对称应手合并计数，但正式库仍需保存可逆坐标，不能直接把统计偏移当成引擎着法。

白二仍只有正邻、斜邻两种我方选择，复用每局原有的八种视角选择；另外三类白二（隔一路正交、走日、远斜）只用于覆盖对手可能的应手，不构成我方随机开局策略。黑三、白四、黑五的全部确认候选都保存在库里，但接管只落暂定主着，不把全部候选等概率随机下。不得直接照搬棋谱出现频率作随机权重。

## 黑三候选清单（已接入）

以下为本轮讨论确认的研究清单：黑一固定 H8，白二按中心八种旋转、镜像归为五类。坐标使用 A–O、1–15；已逐点评估的候选仅保留黑方视角 Rapfi 分数不低于 400 的点，后三类各补入一个尚待同口径评分的 Rapfi 推荐点。

| 白二 | 保留的黑三候选 | 本次补入 |
|---|---|---|
| H9 | I7、I8、I9、H10、I10 | — |
| I9 | I7、I8、G8、J9 | — |
| H10 | G9、G10、G8、F8 | G7（待评） |
| I10 | H9、H10、I8、I9、J9 | G9（待评） |
| J10 | I8、J8、J9、K9、I7、H7 | H6（待评） |

合计 27 个候选条目，其中 24 个已逐点评估、3 个待评。低于 400 的三项已移出：白二 I9 时黑三 J10（257）、白二 H10 时黑三 F10（276）、白二 I10 时黑三 J10（305）。分数来自既有 20 万节点、最多 2 秒的有限搜索，统一为黑方视角；这是本轮候选筛选门槛，不是胜率或最优着法证明。

表中顺序保留讨论顺序，不代表强弱排序或随机概率；三个待评点只取得根推荐，暂不按 400 门槛判定。

这份清单已接入正式前5手库：24 条逐点评分候选按黑方视角保留分数，G7、G9、H6 作为待评覆盖保存（分数为空），主着规则见下节。

## 白四同形合并记录

本轮人工确认以下两支使用同一套白四候选，以第一支为基准，第二支只做坐标变换：

| 前三手 | 白四候选 |
|---|---|
| 黑 H8 → 白 I9 → 黑 G8（基准） | I7、I8、F8 |
| 黑 H8 → 白 I10 → 黑 H9（对应） | G10、H10、H7 |

坐标对应为 I7 → G10、I8 → H10、F8 → H7；第二支此前单独提出的 J9、H10、H11 由上表替代。变换允许两颗同色黑子互换，不保留先后着法身份；这是人工开局候选的局部棋形合并，不表示完整棋盘缓存键相同。

沿用既有 Rapfi 身份、单线程、20 万节点、最多 2 秒设置，本轮重新查询基准局面，根推荐仍为 I7。分别落下白四后查询黑方应手，并将原始 Eval 转为白方视角，结果为 F8：-570、I7：-623、I8：-624。根查询与子局面查询是不同有限搜索上下文，逐点评分排序不必与根推荐一致；保留三个候选，不据此宣布唯一最优点。原始查询和来源身份存于本地实验 `20261105-白四-同形合并复核-Rapfi-Codex-01`。本记录已接入正式前5手库：两个分支各自按人工合并的首选落根（I9/G8 取 I7，I10/H9 取 G10），其余候选保留覆盖。

## 本轮已复算的数字

Python 3.14，输入为本地 `renjunet_v10.rif`。下列结果是这份历史样本的描述：

- Gomoku-Pro 共 679 局，其中 676 局有可用白二；贴身 620/676，即 91.7%；正交隔一路 6/676，即 0.9%。该规则还限制黑三位置，与本项目规则不同。
- Gomoku-Pro 黑胜 433、白胜 201、和棋 45。白胜占全部结果的 29.6%，不是旧脚本误标的 63.8%；和棋计入分母。
- 合并前三手盘面的残余对称后，白四众数占比：疏星 89.7%、浦月 67.4%、寒星 51.7%、瑞星 70.5%、长星 57.4%、斜月 74.5%、彗星 23.3%。这些是等价应手的频率，不是最强着概率。
- 雨月资料中识别到若干弱防，尚不能推出“白方所有应手都弱”。

复算命令为 `python scripts/verify_opening_research.py <本地RIF文件> --section all`，也可用 `--help` 查看分节选项。测试覆盖白胜计数、和棋分母、对称合并和共同坐标系；工具不负责棋谱合法性或定式强弱证明。

## 当前实施与后续验收

本轮已接入整盘前5手稀疏库，接管范围是双方合计第1-5手：黑一 H8；白二正邻/斜邻（对方可选择的三类白二由黑三覆盖）；黑三27条确认候选；白四74条确认分支；黑五429条候选。库中共 103 个完整盘面、511 条候选，其中 102 条暂定主着、2 条白二策略着、7 条待评覆盖。黑五429条在八种旋转/镜像下归并为407条唯一规范候选：5处绝对前四手同形合并，22处同一规范点评分冲突；冲突保留先写并记录来源与两个分数，不后写覆盖，也不静默丢弃。

暂定主着规则：有人工明确首选时遵守人工决定（黑一H8、白二正邻/斜邻策略、白二H10时黑三G9、白四同形合并基准支I7与对应支G10）；否则取同局面、同视角、同口径的已评候选最高分，杀棋优先且步数少者更强，同分按稳定顺序。待评候选只有根推荐，分数为空，不当作最高分或零分，也不参与接管。

纯数据见 `gomoku/core/opening_book_front.py`，由 `scripts/build_opening_front_book.py` 从本地实验数据生成：核对输入为27/74/429、核对教师身份与标签校验和、核对已移出低分项与同形合并删除项，并输出暂定主着汇总表（`--report PATH`）。旧的人类经典推荐与后续研究线（115个明确推荐局面、1个白二备选、4,424个研究线索）仍保存在 `gomoku/core/opening_book_data.py`，但不再接管落点，只在本方第四次落子起补一个普通根候选。

推荐依据与来源见 `gomoku/data/classical_opening_recommendations.json`，纯数据见 `gomoku/core/opening_book_data.py`。通过 `scripts/import_classical_openings.py` 用原始 `.lib` 与清单可复现生成结果和逐条审计；工具校验源 SHA256，原始软件、图谱与注释不入库。

RenLib 下载包内的三份人类编纂树共解析 45,018 个落子节点。总库的白四 252、黑五 639、白六 425 是原始树分支数量，不是唯一局面数，也不代表都值得推荐。总库自述基本图参考书籍、详细变化含编者分析，因此不能将整棵树当作人类经典共识。

本轮采用白四时按完整盘面核对坐标；若正文坐标与页面标记矛盾，或只给出 AI 计算的优劣排序，不以此推导经典主着。保留疏星老定式的白六 I7、浦月的部分经典防守，以及明确注释的少量白六；未核对的路线提前出谱，不能为凑齐六手而补机器建议。


正式改库时验证黑白双方、八种对称、已占点过滤、出谱兜底与战术优先，并同步 Android 引擎及算法文档。本轮已完成上述定向验证与 Android 同步检查，但没有做发布级全量验收，也没有启动界面或长对战。性能和棋力仍须另做对照：固定设置、用官方均衡开局集成对换色，保留旧库基线；研究频率和回归测试通过均不能替代对战结果。
